# UI UX Spec

本文先定义信息结构和操作结构，再谈视觉风格。第一版目标是“只读、完成度够、简单漂亮、能舒服读”，不是做一个视觉演示。

## 1. 主窗口结构

主窗口有两种主要状态：

- 启动面板。
- 阅读页。

阅读页基础布局：

- 左侧：当前容器的 Context Shelf。
- 中央：横向阅读画布。
- 顶部：轻量工具栏。
- 底部：页码/进度区。

不做：

- 复杂多窗口管理。V1 允许多开窗口，但每个窗口独立阅读，不做跨窗口协调。
- 可停靠面板。
- 拖拽组合面板。
- 书架和复杂漫画库管理。

## 2. 启动面板

exe 空启动时显示启动面板。启动面板不是书架，不扫描任何目录。

启动面板显示：

- 应用名 ComicPlate。
- Continue Reading：继续阅读上一次位置；有记录时可显示为 `Continue Reading "BookA.cbz"`。
- Open Comics：打开漫画。

如果 ComicPlate 由文件关联或命令行路径启动，应跳过启动面板，直接打开传入内容。

启动面板不规定具体按钮位置。按钮、图标、布局细节由实现阶段根据 Windows 风格调整。

Continue Reading 行为：

- 点击后直接打开上次正在阅读的内容，并恢复到上次页码。
- 没有可恢复会话时按钮不可用，不额外显示说明文字。
- 不展示完整书架，不扫描上层目录，不展示历史列表。
- 如果上次阅读状态保存了轻量导航上下文，进入阅读页后 Back 可以回到上层容器。
- 如果上层路径已经不存在或无法读取，保留当前内容阅读，并用轻量状态提示说明 Back 不可用。
- 动态名称优先显示有意义的文件夹/压缩包名；单张图片通常文件名无意义，后续 UX 可以显示上层一到两级目录。

Open Comics 行为：

- 入口位于启动面板中央主操作区。
- MVP 阶段可以先复用现有文件夹选择器；后续扩展为文件夹、ZIP/CBZ、图片统一打开。
- 文案先使用英文，UX 阶段再统一本地化。

## 3. 阅读页

阅读页区域：

- 左侧：Context Shelf。
- 中央：横向阅读带。
- 顶部：轻量工具栏。
- 底部：页码/进度条。

Context Shelf MVP 项：

- 显示当前容器一层可打开项。
- Shelf entry：当前层文件夹、ZIP/CBZ。
- 每项显示缩略图或类型占位图。
- ZIP/CBZ 和文件夹 Shelf entry 展示封面缩略图，并叠加类型遮罩或角标。
- 点击 Shelf entry 打开该项或进入该容器。
- 当前层图片不进入左侧栏；它们显示在主阅读/预览面板。

左侧栏关系：

- 左侧导航面板只显示当前容器的一层 Context Shelf。
- 最近打开列表不进入 MVP，也不放进阅读页侧栏作为书架。
- 当前 Book 可以是文件夹、ZIP/CBZ，或后续支持的其他漫画压缩包。
- 左侧导航面板可以隐藏和显示；MVP 先做简单切换，不做动画、不做停靠、不做持久化。
- 左侧导航面板不承担完整文件浏览器职责。MVP 可以有轻量 Back，但不做面包屑路径、树形目录或全量递归播放列表。
- Back 只改变左侧 Context Shelf 的当前容器，不强制清空或重置主阅读面板；它不等同于系统文件浏览器历史。

左侧栏暂不做：

- 书架。
- 文件浏览器式完整后退/前进。
- 路径面包屑。
- metadata 编辑。
- 复杂信息面板。
- 书签。
- 播放列表。
- 可拖拽停靠。
- 用户自定义面板布局。
- 底部缩略图。

Context Shelf 缩略图视觉规则：

- 缩略图尺寸固定，列表滚动时不能因为图片加载导致行高跳动。
- 文件夹 entry 使用文件夹角标或半透明遮罩。
- 压缩包 entry 使用 ZIP/CBZ 角标或半透明遮罩。
- 缩略图加载前显示稳定占位图。
- 缩略图失败时显示稳定错误占位图。
- 缩略图不追求大图质量，优先清楚、稳定、省内存。

横向阅读带 MVP 项：

- 吸附状态下当前阅读组居中。
- 单页模式的当前阅读组是 1 页；双页模式的当前阅读组是 2 页。
- 左右邻近页面按阅读方向排列在同一横向页面流中。
- 当前项目的一次三页可见状态可以作为 MVP 视觉基础，但不能把语义固定成“中心永远是单页”；打开单张图片时单图居中。
- 默认阅读方向为 RightToLeft。
- MVP 可以先限制同时解码和显示的页面数量，但视觉目标是连续 slide 页面流，不是单图查看器。
- 阅读带必须区分两种手感：翻页是吸附，拖拽/滚动是自由。
- Left/Right、键盘翻页、页面列表跳转和单页/双页切换应把目标阅读组带回阅读区中心。
- 鼠标拖拽和连续滚动应直接移动阅读画布；松手后不应因为同步当前页而自动跳回三页窗口中间。
- 自由移动时，页码和当前页高亮可以跟随视口中心最近的页面变化，但画面位置不被强制改写。
- 阅读带使用虚拟化窗口：用户感觉整本书在同一条横向流中，实际只显示和解码视口附近页面。
- 默认使用 AutoFit：普通竖页按阅读区高度尽量放大，横向大图完整适配阅读区。
- 邻近页面可以露出在当前阅读组两侧，也可以被阅读区边界裁掉；不能为了同时完整显示多张邻近页面而把当前阅读组缩成小图。
- 图片保持比例，不裁切。

顶部工具栏 MVP 项：

- 返回启动面板。
- 打开。
- 文件名或书名。
- 适配模式显示。

底部 MVP 项：

- 当前页码：`12 / 96`。
- 显示型进度条。
- 视觉方向翻页控制：`Left` / 当前页码 / `Right`。

底部控制本次已完成：

- `Left` 和 `Right` 是视觉方向按钮，不是固定的上一页/下一页文案。
- RightToLeft 下，`Left` 进入下一阅读组，`Right` 返回上一阅读组。
- LeftToRight 下，`Right` 进入下一阅读组，`Left` 返回上一阅读组。
- 单页模式移动 1 页；双页模式移动 1 个双页阅读组。
- 进度条只显示页码进度，不参与鼠标拖动或点击定位。
- 进度条深色和浅色的交界点表示当前阅读组在阅读带里的大致相对位置。
- 深色区域表示当前阅读组左侧；浅色区域表示当前阅读组右侧。
- RightToLeft 下，第一页位于右侧，进度条初始接近全深色，继续阅读时深色区域向左变短。
- LeftToRight 下，第一页位于左侧，进度条初始接近全浅色，继续阅读时深色区域向右变长。

底部控制 MVP：

- 鼠标滚轮可以先作为离散翻页输入，每次移动一个阅读组并吸附。
- 长期目标是滚轮/触控板可以自由移动阅读带，不自动吸附；明确翻页输入才吸附。

底部控制未来状态：

- 进度条升级为可点击、可拖动的快速定位控件。
- 进度条在双页模式下的精确落点、跨页范围显示和拖动预览交给 V1。
- 横向阅读带后续可以加入更细腻的平滑动画和拖动预览。

工具栏显示策略：

- MVP 可常驻，降低实现风险。
- V1 再做鼠标静止后自动隐藏。

## 4. 全屏模式

状态：V1。

行为：

- 全屏后默认隐藏工具栏。
- 鼠标移动到顶部显示工具栏。
- 鼠标移动到底部显示页码和进度条。
- `Esc` 退出全屏。

## 5. 右键菜单

状态：MVP 必须有约束，具体菜单项可随 UI 实现逐步补齐。

主阅读区：

- Next Page。
- Previous Page。
- Single Page / Double Page。
- Fit to Window。
- Reading Direction。
- Reveal in Finder/Explorer。
- Copy Current File Path。

Context Shelf：

- Open。
- Reveal in Finder/Explorer。
- Copy Path。

Page 导航以后交给底部进度条/缩略图条，不放在左侧栏作为主导航。

不做：

- 可编辑右键菜单。
- 命令参数。
- 脚本命令。
- 删除、移动、重命名、修改原文件。

## 6. 设置页

状态：V1。

设置页分组：

- Reading：阅读方向、单页/双页、封面单独显示。
- Display：适配窗口、背景色、图片插值质量。
- Progress：是否自动恢复进度、进度记录上限。
- File Associations：是否关联 ZIP/CBZ、后续 CBR/CB7，以及是否作为图片查看器。
- Shortcuts：V1 做快捷键预设或少量自定义；MVP 不做快捷键设置页。

MVP 不做设置页，但内部配置结构要能支持这些未来项。

## 7. 快捷键

MVP 不做快捷键设置界面，只保留固定核心快捷键。V1 再做快捷键预设或少量自定义。

跨平台通用：

- `Right Arrow`：下一页。
- `Left Arrow`：上一页。
- `Space`：下一页。
- `Backspace`：上一页。
- `Home`：第一页。
- `End`：最后一页。
- `F11`：全屏，Windows 优先。
- `Esc`：退出全屏或返回普通状态。

macOS 差异：

- 打开：`Cmd+O`。
- 设置：`Cmd+,`。
- 退出：系统默认 `Cmd+Q`。

Windows 差异：

- 打开：`Ctrl+O`。
- 设置：`Ctrl+,`。
- 全屏：`F11`。

## 7.1 多窗口

状态：V1。

行为：

- 用户可以打开多个 ComicPlate 阅读器窗口。
- 每个窗口都是完整阅读器，可以独立打开一本漫画或一个可阅读单元。
- 每个窗口独立保存当前 Book 的阅读进度。
- 不做跨窗口同步、窗口布局恢复、全局阅读队列或书库协调。

## 8. 视觉风格

第一版原则：

- 背景克制，优先服务图片。
- 阅读页不要有装饰性卡片。
- 控件小而清楚。
- Windows 版本优先。
- 浅灰色工具应用风格优先，参考 OneCommander / WinUI 3 的克制、密集、清楚。
- 深色模式可以后续补，不作为当前第一目标。
- 暂不追求 macOS 视觉方向。

macOS：

- 接近 macOS 原生应用的轻量感。
- 使用系统菜单习惯。
- 不在第一版追求复杂透明材质，但视觉方向参考 macOS 26。

Windows：

- 接近 Win11 的简洁工具应用。
- 不在第一版追求 Mica。
- 侧栏、工具栏、列表和状态区可以采用浅灰分区、细边框、小控件、低圆角。
- 图片区域仍然是视觉主角，工具区不喧宾夺主。

## 9. 体验基准

每次 UI 改动后检查：

- 1200x800 是否能舒服阅读。
- 800x600 是否不遮挡主要内容。
- macOS 和 Windows 快捷键文案是否正确。
- 图片区域是否永远是视觉主角。
- 工具栏和页码是否不会遮住图片关键区域。
