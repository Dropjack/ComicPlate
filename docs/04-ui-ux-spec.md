# UI UX Spec

本文先定义信息结构和操作结构，再谈视觉风格。第一版目标是“只读、完成度够、简单漂亮、能舒服读”，不是做一个视觉演示。

## 1. 主窗口结构

主窗口有两种主要状态：

- 启动页。
- 阅读页。

阅读页基础布局：

- 左侧：书架侧栏和页面列表侧栏。
- 中央：横向阅读画布。
- 顶部：轻量工具栏。
- 底部：页码/进度区。

不做：

- 多窗口。
- 可停靠面板。
- 拖拽组合面板。
- 复杂书架管理。

## 2. 启动页

启动页显示：

- 应用名 ComicPlate。
- 打开书架根目录入口。
- 最近打开列表。

最近打开列表每项显示：

- 书名：文件夹名或压缩包文件名。
- 路径，弱化显示。
- 上次阅读页码，如 `42 / 180`。
- 最后打开时间。

空最近列表：

- 显示简短空状态，不写长说明。

启动页不规定具体按钮位置。按钮、图标、布局细节由实现阶段根据 Windows 风格调整。

## 3. 阅读页

阅读页区域：

- 左侧：书架面板和页面列表面板。
- 中央：横向阅读带。
- 顶部：轻量工具栏。
- 底部：页码/进度条。

书架面板 MVP 项：

- 当前书架根目录下递归发现的漫画书列表。
- 文件夹 Book 显示为文件夹漫画。
- `.zip` 和 `.cbz` 显示为压缩包漫画。
- 工程上文件夹漫画和 ZIP/CBZ 漫画统一称为 Book。
- 默认按名称自然排序。
- 点击某本书打开阅读。
- 书架项目标显示首页缩略图；缩略图加载必须有缓存上限，不能为了书架一次性解码整套漫画。

页面列表面板 MVP 项：

- 当前 Book 的页面列表。
- 页码。
- 文件名或简化文件名。
- 当前页高亮。
- 点击某页跳转。

左侧栏关系：

- 书架和页面列表是同一个左侧导航面板里的两个页签。
- 两个页签占用同一个位置，内容不同。
- 书架显示漫画书，页面列表显示当前漫画书里的页面。
- 不把书架和页面列表混成同一个列表。
- 左侧导航面板可以隐藏和显示；MVP 先做简单切换，不做动画、不做停靠、不做持久化。

左侧栏暂不做：

- metadata 编辑。
- 复杂信息面板。
- 书签。
- 播放列表。
- 可拖拽停靠。
- 用户自定义面板布局。
- 页面列表缩略图和底部缩略图。书架首页缩略图属于书架项展示目标，但必须有缓存上限。

横向阅读带 MVP 项：

- 当前页居中。
- 前后页按阅读方向排列在同一横向页面流中。
- 默认阅读方向为 RightToLeft。
- MVP 可以先限制同时解码和显示的页面数量，但视觉目标是连续页面流，不是单图查看器。
- 默认使用 AutoFit：普通竖页按阅读区高度尽量放大，横向大图完整适配阅读区。
- 前后邻页可以露出在当前页两侧，也可以被阅读区边界裁掉；不能为了同时完整显示多张邻页而把当前页缩成小图。
- 图片保持比例，不裁切。

顶部工具栏 MVP 项：

- 返回启动页。
- 打开。
- 文件名或书名。
- 适配模式显示。

底部 MVP 项：

- 当前页码：`12 / 96`。
- 显示型进度条。
- 视觉方向翻页控制：`Left` / 当前页码 / `Right`。

底部控制本次已完成：

- `Left` 和 `Right` 是视觉方向按钮，不是固定的上一页/下一页文案。
- RightToLeft 下，`Left` 进入下一页，`Right` 返回上一页。
- LeftToRight 下，`Right` 进入下一页，`Left` 返回上一页。
- 进度条只显示页码进度，不参与鼠标拖动或点击定位。
- 进度条深色和浅色的交界点表示当前页在阅读带里的相对位置。
- 深色区域表示当前页左侧；浅色区域表示当前页右侧。
- RightToLeft 下，第一页位于右侧，进度条初始接近全深色，继续阅读时深色区域向左变短。
- LeftToRight 下，第一页位于左侧，进度条初始接近全浅色，继续阅读时深色区域向右变长。

底部控制未来状态：

- 鼠标滚轮加入为离散翻页输入。
- 进度条升级为可点击、可拖动的快速定位控件。
- 横向阅读带后续可以加入平滑滑动和拖动预览。

工具栏显示策略：

- MVP 可常驻，降低实现风险。
- V1 再做鼠标静止后自动隐藏。

## 4. 全屏模式

状态：V1。

行为：

- 全屏后默认隐藏工具栏。
- 鼠标移动到顶部显示工具栏。
- 鼠标移动到底部显示页码和进度条。
- `Esc` 退出全屏。

## 5. 右键菜单

状态：MVP 必须有约束，具体菜单项可随 UI 实现逐步补齐。

主阅读区：

- Next Page。
- Previous Page。
- Single Page / Double Page。
- Fit to Window。
- Reading Direction。
- Reveal in Finder/Explorer。
- Copy Current File Path。

目录侧栏：

- Jump to Page。
- Reveal in Finder/Explorer。
- Copy Path。

最近打开列表：

- Open。
- Reveal in Finder/Explorer。
- Copy Path。
- Remove from Recent。

不做：

- 可编辑右键菜单。
- 命令参数。
- 脚本命令。
- 删除、移动、重命名、修改原文件。

## 6. 设置页

状态：V1。

设置页分组：

- Reading：阅读方向、单页/双页、封面单独显示。
- Display：适配窗口、背景色、图片插值质量。
- Library：是否自动恢复进度、最近打开数量。
- Shortcuts：只展示固定快捷键，先不允许编辑。

MVP 不做设置页，但内部配置结构要能支持这些未来项。

## 7. 快捷键

跨平台通用：

- `Right Arrow`：下一页。
- `Left Arrow`：上一页。
- `Space`：下一页。
- `Backspace`：上一页。
- `Home`：第一页。
- `End`：最后一页。
- `F11`：全屏，Windows 优先。
- `Esc`：退出全屏或返回普通状态。

macOS 差异：

- 打开：`Cmd+O`。
- 设置：`Cmd+,`。
- 退出：系统默认 `Cmd+Q`。

Windows 差异：

- 打开：`Ctrl+O`。
- 设置：`Ctrl+,`。
- 全屏：`F11`。

## 8. 视觉风格

第一版原则：

- 背景克制，优先服务图片。
- 阅读页不要有装饰性卡片。
- 控件小而清楚。
- Windows 版本优先。
- 浅灰色工具应用风格优先，参考 OneCommander / WinUI 3 的克制、密集、清楚。
- 深色模式可以后续补，不作为当前第一目标。
- 暂不追求 macOS 视觉方向。

macOS：

- 接近 macOS 原生应用的轻量感。
- 使用系统菜单习惯。
- 不在第一版追求复杂透明材质，但视觉方向参考 macOS 26。

Windows：

- 接近 Win11 的简洁工具应用。
- 不在第一版追求 Mica。
- 侧栏、工具栏、列表和状态区可以采用浅灰分区、细边框、小控件、低圆角。
- 图片区域仍然是视觉主角，工具区不喧宾夺主。

## 9. 体验基准

每次 UI 改动后检查：

- 1200x800 是否能舒服阅读。
- 800x600 是否不遮挡主要内容。
- macOS 和 Windows 快捷键文案是否正确。
- 图片区域是否永远是视觉主角。
- 工具栏和页码是否不会遮住图片关键区域。
