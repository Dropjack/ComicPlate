# Decisions

这里记录已经达成共识的产品和工程决定。它比长文档更像“裁判记录”：以后如果范围摇摆，先看这里。

## D001 - 只读阅读器

Status: Accepted
Date: 2026-04-25

决定：

ComicPlate MVP 是只读漫画阅读器，不是漫画文件管理器。

影响：

- 不删除用户图片。
- 不移动用户图片。
- 不重命名用户图片。
- 不修改压缩包。
- 不写回 metadata。
- 只写 ComicPlate 自己的设置、进度、日志和缓存。

## D002 - 双页进入第一批

Status: Accepted
Date: 2026-04-25

决定：

双页模式和阅读方向是第一批核心体验。单页技术闭环跑通后立刻实现。

原因：

用户大部分时间按双页习惯阅读，双页是 NeeView 阅读舒适感的重要部分。

## D003 - 递归保留为核心模式

Status: Accepted
Date: 2026-04-25

决定：

递归文件夹阅读要保留，但必须写清楚边界。

边界：

- 不把子文件夹当页面。
- 递归开启时收集子文件夹内图片。
- 按相对路径自然排序。
- 权限失败或空子目录不能导致应用崩溃。

## D004 - MVP 要有基础目录侧栏

Status: Accepted
Date: 2026-04-25

决定：

MVP 要有基础目录侧栏。底部缩略图可以后做；浮窗可以在 MVP 稳定后评估；拖拽组合和复杂停靠永久不做。

原因：

ComicPlate 不是裸图窗口，而是保留 NeeView 基础阅读结构、完成度够的阅读器。

## D005 - 不做书签，保留阅读进度

Status: Accepted
Date: 2026-04-25

决定：

MVP 不做书签。每本书自动恢复上次阅读页。

原因：

用户长期使用 NeeView 也基本不用书签，自动进度恢复更符合实际需求。

## D006 - 简单 Action，不做复杂命令系统

Status: Accepted
Date: 2026-04-25

决定：

ComicPlate 使用固定 Action 支撑快捷键、工具栏和右键菜单，不做 NeeView 式可编辑、可复制、可脚本扩展的复杂命令系统。

影响：

- 不做脚本命令。
- 不做命令参数编辑器。
- 不做用户自定义右键菜单。
- 不同区域的右键菜单需要在 UI/UX 和 Behavior 文档中单独定义。
