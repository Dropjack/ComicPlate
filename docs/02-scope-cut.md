# Scope Cut

本文是 ComicPlate 的范围刹车。任何功能进入开发前，先看这里。

`02` 只决定做不做、先不先做。具体行为写入 `03-behavior-spec.md`，界面结构和交互文案写入 `04-ui-ux-spec.md`。

标签说明：

- MVP 必须有：没有它就不是可用的轻量漫画阅读器。
- V1 可以有：MVP 稳定后再加。
- 以后再说：现在不设计，不为它预留复杂架构。
- 永久不做：至少第一年不碰，除非项目目标重写。

## 产品方向

ComicPlate 的最新方向：

- 为本地漫画内容设计的跨平台漫画预览器/阅读窗口。
- 少设置，专注连续阅读。
- 记住用户读到哪，但不替用户管理藏书。
- 不识别“漫画作品”，只识别“可阅读单元”。
- 用户打开什么范围，ComicPlate 就把这个范围解释成一本临时 Book，并生成线性 Page 流。
- 阅读交互分为两类：翻页模式是“吸附”，拖拽/滚动模式是“自由”。按钮、快捷键等明确翻页动作应回到单页/双页阅读组中心；拖拽和连续滚动应移动阅读画布本身，不应每次自动拉回当前页中心。

因此，ComicPlate 不做漫画库管理器。它可以打开一个大目录、一个章节目录、一个单行本压缩包，甚至一个包含多卷压缩包的合集目录；但它不自动判断哪些内容属于同一部作品，也不把它们拆成书架。

## 阅读核心

| 功能 | 标签 | 原因 |
| --- | --- | --- |
| 文件夹作为可阅读单元打开 | MVP 必须有 | 常见漫画来源，也是最小闭环入口 |
| ZIP/CBZ 作为可阅读单元打开 | MVP 必须有 | 常见漫画来源，必须进入第一版完整闭环 |
| 显示第一张图片 | MVP 必须有 | 垂直切片核心 |
| 左右键翻页 | MVP 必须有 | 阅读器基本操作 |
| 单页适配窗口 | MVP 必须有 | 保证打开就能看 |
| 自然排序 | MVP 必须有 | 漫画文件名常含数字 |
| 空文件夹/空压缩包提示 | MVP 必须有 | 必须有清楚失败状态 |
| 损坏图片提示并可跳过 | MVP 必须有 | 真实素材会出错 |
| 记住当前页 | MVP 必须有 | 阅读体验关键 |
| 最近打开列表 | MVP 必须有 | 让阅读窗口记得上下文，但不承担藏书管理 |
| 单张图片居中显示 | MVP 必须有 | 没有书架后，单图打开可以作为轻量预览入口 |
| 双页模式 | MVP 必须有 | 用户主要阅读习惯，也是 NeeView 核心舒适感之一 |
| 日漫/欧美阅读方向切换 | MVP 必须有 | 双页显示和左右键映射都依赖它 |
| 基础页面列表侧栏 | MVP 必须有 | 保留当前 Book/Page 结构，方便跳页 |
| 横向连续阅读带 | MVP 必须有 | 阅读画布应呈现连续页面流，当前阅读组居中，接近 NeeView 阅读心智 |
| 鼠标滚轮翻页 | MVP 必须有 | 低成本且符合阅读器常用操作 |
| 虚拟化阅读带 | MVP 必须有 | 逻辑上支持整本书连续页面流，实际只加载视口附近页面，避免一次性解码整本漫画 |
| 全屏模式 | V1 可以有 | 体验增强，不阻塞第一版阅读闭环 |
| 鼠标拖拽自由移动阅读带 | MVP 必须有 | NeeView 式连续阅读手感的核心；拖拽移动画布，不等同于离散翻页 |
| 页列表缩略图 | 以后再说 | 容易引入缓存和 UI 复杂度 |
| 书签 | 永久不做 | 自动恢复上次页已覆盖个人需求 |
| 播放列表 | 永久不做 | 偏 NeeView 高级功能 |

说明：

- 单页阅读可以作为最初技术切片先跑通，但双页必须进入 MVP 第一批核心体验。
- 页面列表显示当前可阅读单元里的页面。工程上统一把当前打开范围称为 Book，把图片页称为 Page。
- Book 不是藏书库条目，而是用户本次选择路径形成的阅读单元。
- MVP 的阅读画布不应只是单个孤立图片控件；应按横向连续阅读带设计，当前阅读组居中，左右邻近页面在同一横向流中显示或预备显示。
- 单页模式的当前阅读组是 1 页，双页模式的当前阅读组是 2 页。翻页、按钮和滚轮移动的是阅读组，不是简单替换中心图片。
- “当前阅读组居中”只适用于吸附动作：打开、跳页、Left/Right、快捷键、切换单页/双页模式。拖拽和连续滚动期间，阅读带应保持自由 offset，不自动居中。
- 虚拟化是 MVP 阅读带的架构目标：Book/Page 业务层只提供线性 Page 流；阅读视图层维护阅读带 offset、可见窗口、图片缓存和释放策略。
- MVP 默认只做 Fit 适配窗口：完整显示图片、保持比例、不裁切。
- 拉伸、旋转、自由缩放、滤镜、裁切白边都不进入 MVP。

## 文件来源

| 功能 | 标签 | 原因 |
| --- | --- | --- |
| 文件夹图片扫描 | MVP 必须有 | 核心输入 |
| 支持 jpg/jpeg/png/webp/bmp | MVP 必须有 | 常见漫画/图片格式 |
| gif 仅显示第一帧 | MVP 必须有 | 只读静态图片，不做动画播放 |
| ZIP/CBZ 打开 | MVP 必须有 | 漫画常见格式，和文件夹同属可阅读单元来源 |
| 压缩包内非图片忽略 | MVP 必须有 | 常见元数据文件不应打断阅读 |
| 子文件夹递归扫描 | MVP 必须有 | 保留文件夹漫画/章节目录/合集目录阅读能力 |
| 压缩包内子目录图片扫描 | MVP 必须有 | CBZ/ZIP 常见章节结构 |
| 文件夹内 ZIP/CBZ 串联阅读 | MVP 必须有 | 手头漫画大量以多卷压缩包合集目录存在 |
| RAR/CBR | V1 可以有 | 漫画常见格式，需要额外库或平台测试 |
| 7z/CB7 | V1 可以有 | 漫画常见格式，但复杂度高于 ZIP |
| 嵌套压缩包 | 永久不做 | 难度和边界都高 |
| PDF | 永久不做 | 会改变产品范围 |
| EPUB/MOBI | 永久不做 | 电子书阅读不是 ComicPlate |
| 视频/音频 | 永久不做 | 不是 ComicPlate |
| Susie 插件 | 永久不做 | Windows 特化且复杂 |

说明：

- ComicPlate 的输入范围就是图片文件夹和漫画压缩包。
- `Open` 是把用户选择的路径作为一本 Book 打开，不是选择书架根目录。
- 文件夹可以是一本 Book，ZIP/CBZ 也可以是一本 Book。
- 文件夹 Book 内部默认递归读取支持格式图片，并按相对路径自然排序。
- 文件夹里如果直接或间接包含多个 ZIP/CBZ，MVP 要把这些压缩包的页面串进同一个 Book。
- 文件夹 Book 的页面流可以同时包含普通图片和 ZIP/CBZ 内图片；排序按外部相对路径自然排序，压缩包内部再按内部逻辑路径自然排序。
- 打开某个 ZIP/CBZ 后，读取压缩包内图片，并按压缩包内逻辑路径自然排序。
- ZIP/CBZ 内部可以有子目录图片，但压缩包套压缩包不进入 MVP，也不为它预留复杂结构。
- 非图片文件默认忽略，不作为页面，也不提示。
- 递归扫描要守住边界：只收集支持格式的图片，不把子文件夹本身当页面。
- 压缩包读取不写回用户文件，也不把内容解压到用户目录。

## UI 和操作

| 功能 | 标签 | 原因 |
| --- | --- | --- |
| 空阅读面板：打开一本漫画、最近打开 | MVP 必须有 | 入口必须清楚 |
| 阅读页：横向阅读带、页码、简单工具栏 | MVP 必须有 | 足够使用且保留连续阅读心智 |
| 基础页面列表侧栏 | MVP 必须有 | 显示当前 Book 的 Page，方便跳页 |
| 分区域右键菜单约束 | MVP 必须有 | 主阅读区、目录侧栏、最近列表行为必须清楚 |
| 右键菜单基础项 | MVP 必须有 | 需要有清楚入口，但菜单项可按实现逐步补齐 |
| 工具栏自动隐藏 | V1 可以有 | MVP 可常驻或轻量显示 |
| 设置页基础组 | V1 可以有 | MVP 可先用默认配置和内部配置文件 |
| macOS/Windows 快捷键差异 | V1 可以有 | MVP 可先保证核心键 |
| 全屏专用 UI 行为 | V1 可以有 | 跟全屏模式一起做 |
| 底部缩略图 | V1 可以有 | 重要体验，但可晚于基础目录侧栏 |
| 浮窗侧栏 | V1 可以有 | MVP 稳定后立即评估 |
| 快捷键设置 | V1 可以有 | MVP 使用固定核心快捷键，V1 再做预设或少量自定义 |
| Win11 Mica/macOS 视觉抛光 | 以后再说 | 不阻塞可用 |
| 拖拽组合/复杂停靠面板 | 永久不做 | 超出轻量目标 |
| 多窗口支持 | V1 可以有 | 每个窗口是一套完整独立阅读器，方便同时读设定集和正文 |
| 多窗口管理器 | 永久不做 | 不做跨窗口书库、同步或复杂协调 |
| 可编辑右键菜单/命令系统 | 永久不做 | 会把轻量阅读器拖向复杂工具平台 |

说明：

- 空阅读面板必须有明确打开入口和最近打开入口。
- 阅读页的视觉主角永远是图片，不做装饰性卡片和复杂面板。
- 左侧栏至少包含当前 Book 的页面列表；不做书架、信息、书签、播放列表、metadata 编辑等高级侧栏。
- 右键菜单必须遵守只读原则：不删除、移动、重命名、修改用户文件。
- 具体布局、菜单项和快捷键文案在 `04-ui-ux-spec.md` 收束。

## 系统和架构

| 功能 | 标签 | 原因 |
| --- | --- | --- |
| Avalonia 跨平台项目 | MVP 必须有 | macOS/Windows 双版本基础 |
| Book/Page 模型 | MVP 必须有 | 保留 NeeView 最舒服的核心隐喻 |
| 可阅读单元打开器 | MVP 必须有 | 从用户选择的路径生成 Book 和 Page |
| MVVM 最小结构 | MVP 必须有 | 保持 UI 和状态分离 |
| JSON 配置和进度文件 | MVP 必须有 | 低复杂度持久化 |
| 只读用户内容 | MVP 必须有 | 不删除、移动、重命名、修改用户图片或压缩包 |
| 基础缓存/释放策略 | MVP 必须有 | 图片阅读不能持续吃内存 |
| 基础日志 | V1 可以有 | 调试打包后问题 |
| 自动更新 | 永久不做 | 个人工具不需要 |
| 插件化架构 | 永久不做 | 会拖慢 MVP |
| 复杂命令系统 | 永久不做 | 当前阶段不是目标 |
| 主题编辑器 | 永久不做 | 高成本低必要 |

说明：

- Book ID 使用规范化绝对路径即可，MVP 不做内容 hash。
- Book ID 指用户打开的路径。文件夹合集、单个压缩包、后续单图范围都按各自打开路径保存进度。
- 如果路径变化，ComicPlate 可以把它当作一本新书，从头开始读。
- 所有写入只发生在 ComicPlate 自己的配置、进度、最近打开、日志或缓存中。

## MVP 的真实定义

MVP 不是“功能看起来很多”。ComicPlate 的 MVP 是：

1. 启动应用。
2. 选择一个文件夹或 ZIP/CBZ，把它作为一本 Book 打开。
3. 程序扫描、过滤并自然排序图片。
4. 如果打开的是文件夹，默认递归收集其内部图片。
5. 如果文件夹内包含 ZIP/CBZ，串联读取这些压缩包内图片。
6. 单张图片可以居中显示。
7. 阅读画布以横向连续阅读带显示页面，当前阅读组居中，左右邻近页面参与同一横向流。
8. Left/Right 按钮、左右键和鼠标滚轮移动当前阅读组。
9. 支持单页、双页和阅读方向，默认阅读方向偏向日漫右到左。
10. 有基础页面列表侧栏。
11. 能显示空状态和损坏图片占位，不崩溃。
12. 关闭后再次打开同一路径，可以恢复上次页。
13. 在空阅读面板看到最近打开，并能再次进入阅读。

MVP 不包含：

- 设置窗口。
- 快捷键设置。
- 可交互进度条。
- 主题编辑器。
- 插件。
- 脚本。
- 全屏。
- 复杂可停靠/拖拽组合面板。
- 页面列表缩略图和底部缩略图。
- 书签。
- 文件管理。不承担删除、移动、重命名等管理能力。
- 导出。
- PDF/EPUB/MOBI/视频/音频阅读。
